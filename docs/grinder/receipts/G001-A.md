## Delivered contract

Lane A provides Houdini-independent immutable request/result/summary structures for schema
`hermes.houdini.acceptance.v1`, finite budget and observation validation, narrow artifact-root
validation, deterministic canonical JSON and SHA-256 summaries, and mechanical evidence-state
aggregation. Wall-clock `started_at` and `duration_seconds` values remain reportable but are excluded
from the semantic summary hash, as is the top-level self-hash field.

The runner creates a non-executing plan, adds only the cheap `pure` and `hython-read` prerequisites,
maps missing adapters to `pending`, maps timeouts and invalid/failed adapters to `blocked`, and never
grants approvals. The single CLI lists tiers, defaults to help, creates non-executing plans, and
requires explicit tiers plus a narrow absolute artifact root for execution.

## Contract and integration notes

- Pure import surface: `hermes_houdini.acceptance`; direct verification confirmed that importing it
  does not add `hou` to `sys.modules`.
- `TierAdapter.run(*, tier, artifact_root, budget) -> Mapping[str, Any]` is the narrow seam for Lane
  B/C providers. `AcceptanceRunner(adapters={tier_id: adapter})` performs registration.
- Adapters return the frozen plain mapping fields. The runner supplies the explicit artifact root to
  artifact validation and rejects results for the wrong tier.
- The integration captain owns imports of Lane B/C adapters and registration in
  `scripts/run_acceptance.py`; no schema changes are required.
- `--plan` performs no adapter call, child-process spawn, artifact directory creation, cook, render,
  or Houdini import. Expensive tiers appear only when the operator explicitly selects them.
