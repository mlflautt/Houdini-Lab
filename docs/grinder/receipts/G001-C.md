## H22 probe provenance

Before encoding the built-in expectation, a read-only `hython -c` probe inspected
`hou.sopNodeTypeCategory().nodeTypes()["box"].parmTemplates()` on live Houdini Apprentice
`22.0.368`. It reported category `Sop`, operator `box`, and these exact parameter signatures:

```text
type Menu 0; surftype Menu 4; consolidatepts Toggle true;
size Float [1,1,1]; t Float [0,0,0]; r Float [0,0,0]; scale Float [1];
divrate Int [4,4,4]; orderrate Int [4,4,4]; dodivs Toggle false;
divs Int [3,3,3]; rebar Toggle false; orientedbbox Toggle false;
vertexnormals Toggle false
```

The probe read operator definitions only: it created no node, cooked nothing, changed no frame/HIP/UI
state, and wrote no file.

## Contracts and adapter signatures

- `normalize_baseline(baseline) -> dict`
- `evaluate_baseline(baseline, observed) -> dict`
- `normalize_expectation(expectation) -> dict`
- `compare_compatibility(expectation, observation) -> dict`
- `probe_compatibility(expectation, *, output_path=None) -> dict`

The baseline record covers points, primitives, peak memory bytes, cook seconds, cache bytes, frames,
width, height, render samples, default warning tolerance, and per-metric overrides. Metric outcomes
are `missing`, `within_budget`, `warning`, `hard_violation`, and `invalid`; top-level evidence states
remain `pass|warn|pending|blocked`. Invalid non-finite input never leaks NaN/Infinity into result JSON.

Compatibility expectations include context, exact category/operator, required and optional
parameters, safe type/default expectations, and inclusive tested build range. Results retain exact
live build/license and structured human-readable diffs. The lazy Hython adapter reads node-type
definitions only and writes exclusively when an explicit non-existing output path is supplied.
